# 11 Pi 应用与归一化入口 · 学习笔记

> README 核心问题：怎么 build 一个 UI bot 或 CLI，把工作流归一化到一个 agent 入口？
> 证据来源：`core/sdk.ts`（`createAgentSession`）、`packages/agent/src/agent.ts`（`new Agent`）、`modes/*`、`packages/web-ui`、`examples/sdk/*`。
> 一句话：pi 有两个入口层级——`new Agent`（纯 turn 引擎）和 `createAgentSession`（Agent + 一整套设施）；同一个 AgentSession 能被 print/interactive/rpc/web 多种形态复用，"归一化入口"= 把分散工作流都收到这一个 agent 上。

---

## 题眼：一个 agent 内核，多种外壳

前十篇拆的是 agent 内部机制（loop/tool/session/context/skill/extension）。这一篇反过来：**这些机制怎么被包成一个能用的应用入口。**

pi 的答案是分两层入口 + 多种运行形态：
- **两层入口**：`new Agent`（core，什么都自己装）vs `createAgentSession`（应用层，设施齐全）。
- **多种形态**：同一个 AgentSession，可以跑成 CLI 单发（print）、TUI 交互（interactive）、远程调用（rpc）、浏览器聊天（web-ui）。

"归一化"就是：不管前端是 CLI、web 还是 bot，后面都是同一个 agent 入口。

---

## 一、createAgentSession：SDK 入口（`sdk.ts`）

```ts
async function createAgentSession(options = {}): Promise<CreateAgentSessionResult>
```
返回 `{ session: AgentSession, extensionsResult, modelFallbackMessage }`。选项全部可选（authStorage / modelRegistry / model / sessionManager / resourceLoader / customTools / noTools / tools 等）。

**内部装配顺序**（sdk.ts，已核实）：
```
AuthStorage.create → ModelRegistry.create → SettingsManager.create
  → SessionManager.create → new DefaultResourceLoader(...).reload()
  → 模型解析 findInitialModel + clampThinkingLevel
  → 工具白名单 defaultActiveToolNames = ["read","bash","edit","write"]
  → new Agent({ ... , streamFn })       ← core 引擎
  → new AgentSession({ ... })           ← 包一层设施
```

**一个关键设计**：给 Agent 注入的 `streamFn` 是个闭包——内部先 `modelRegistry.getApiKeyAndHeaders(model)` 再调 `streamSimple`。**即 core 不碰鉴权，鉴权在这层闭包里解决**。这就是分层：core 只管"发请求"，"用哪个 key、什么 header"是 createAgentSession 这层填的。

## 二、new Agent vs createAgentSession（分工边界）

`new Agent`（agent.ts）是**纯 turn 引擎**：
- 构造 `AgentOptions` 全可选（initialState / convertToLlm / streamFn / getApiKey…）。
- 方法：`prompt()` / `continue()` / `subscribe()` / `steer()` / `followUp()` / `abort()` / `waitForIdle()` / `reset()` / `get state`。
- 底层跑 `runAgentLoop`。

**core 有什么、没什么**：
| | core（new Agent） | createAgentSession 加的 |
|---|---|---|
| transcript + 事件 + 工具执行 + 队列 | ✅ | — |
| 鉴权（AuthStorage） | ✗ | ✅ streamFn 闭包 |
| 模型解析（ModelRegistry） | ✗ | ✅ |
| 会话持久化/恢复（SessionManager） | ✗ | ✅ `agent.state.messages = existingSession.messages` |
| 资源加载（ResourceLoader） | ✗ | ✅ |
| 内置工具 / skill / extension | ✗ | ✅ |

→ **边界清楚**：`new Agent` 适合"已有自己的存储/协议/模型路由，只缺对话内核"；`createAgentSession` 适合"想要 skill/extension/memory 地基"。（crbuddy 最初用 new Agent，后为要 skill/agent/memory 迁到 createAgentSession——见 05/06 实战。）

## 三、运行形态：一个 session，多种模式（`modes/`）

`main.ts` 按 `appMode` 派发三种（rpc / interactive / 其余=print）：

| 模式 | 入口 | 场景 |
|---|---|---|
| **print** | `runPrintMode` | CLI 单发即退（`pi -p` 文本，`--mode json` 事件流） |
| **interactive** | `InteractiveMode` | TUI 交互（终端 UI） |
| **rpc** | `runRpcMode` | 远程/程序调用（JSON-over-stdio） |

**rpc mode 怎么把 agent 变成可远程调用的**（rpc-mode.ts，已核实）：
```
takeOverStdout() → attachJsonlLineReader(stdin, ...)   // 读 JSON 行
  → handleCommand switch(prompt/steer/follow_up/abort/get_state/set_model/compact/fork…)
  → session.subscribe(event => writeRawStdout(serializeJsonLine(event)))  // 事件写 stdout
```
→ **JSON-over-stdio**：stdin 进命令、stdout 出事件流，把 AgentSession 暴露成一个可被任意进程驱动的服务。这是"归一化"的关键——任何前端只要会读写这套 JSON 协议，就能驱动同一个 agent。

## 四、web-ui 入口（`packages/web-ui`）

- 基于 **lit web component**：`@customElement("pi-chat-panel") class ChatPanel extends LitElement`。
- **复用的是 core `new Agent`**，不走 createAgentSession：`new Agent(...)` 再 `chatPanel.setAgent(agent, {...})`。
- 持久化/鉴权用浏览器侧设施：`IndexedDBStorageBackend` + `SessionsStore/ProviderKeysStore`，streamFn 走 `createStreamFn`/proxy。

→ **web-ui 复用 core Agent，自带一套浏览器设施替代 coding-agent 的 Node 设施**。这印证分层价值：core 是 UI 无关的内核，Node 端和浏览器端各配自己的存储/鉴权/传输。

## 五、最小可跑应用（`examples/sdk/`）

**全默认版**（`01-minimal.ts`，真实源码）：
```ts
import { createAgentSession } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession();   // 全默认：自动发现 skill/extension/tool、从 settings 选模型
session.subscribe((event) => {
  if (event.type === "message_update" && event.assistantMessageEvent.type === "text_delta") {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});
await session.prompt("What files are in the current directory?");
session.dispose();
```

**显式版必需步骤**（`12-full-control.ts`）：
```
① AuthStorage.create()
② ModelRegistry.create(authStorage)
③ getModel("anthropic", "...")
④ createAgentSession({ model, authStorage, modelRegistry, tools, sessionManager })
⑤ session.subscribe(...)
⑥ await session.prompt(...)
⑦ session.dispose()
```
最小版 ①②③ 可省（用默认）。

→ 一个 pi 应用的骨架就这么点：建 session → 订阅事件 → prompt → dispose。前面十篇的所有机制，都在 `createAgentSession` 这一行背后装配好了。

## 六、"归一化入口"是什么意思

把散落的工作流收到一个 agent 入口，具体指：
- **一个内核**（AgentSession / Agent），承载 loop/tool/session/context/skill/extension 全部机制。
- **多个外壳**（print/interactive/rpc/web），各自把这个内核接到不同前端。
- **一套协议**（rpc 的 JSON-over-stdio），让任何前端都能驱动同一个 agent。

所以"build 一个 UI bot 或 CLI"不是各写一套 agent 逻辑，而是：写好一个 createAgentSession（或 new Agent），然后选个形态（或自定义一个，像 crbuddy 的 web server + SSE）把它暴露出去。**agent 逻辑只有一份，入口形态可以有多种。**

---

## 一句话总结

pi 两层入口：`new Agent`（纯 turn 引擎，自己装配一切）、`createAgentSession`（Agent + SessionManager/ModelRegistry/ResourceLoader/工具/skill/extension，鉴权在 streamFn 闭包里）。同一个 session 可跑成 print/interactive/rpc/web 多种形态，rpc 的 JSON-over-stdio 让任意前端驱动同一 agent。归一化 = agent 逻辑一份、入口形态多种。
