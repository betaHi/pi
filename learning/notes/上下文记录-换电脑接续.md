## 四、已查证的核心结论（tool 系统，05/06 篇的依据）

详细版在 `learning/notes/04-下篇-待查问题.md`。要点：

- **工具三个来源**汇进一个 registry（`_refreshToolRegistry`）：① 内置 `_baseToolDefinitions` ② extension `getAllRegisteredTools()` ③ SDK `_customTools`。同名后者覆盖前者。
- **core 只认 `agent.state.tools`** 一个数组，不管来源、不管数量。工具数量管理（白名单 + active tools）在 coding-agent。
- **工具走 API 原生 tools 字段**（不是塞 prompt）；system prompt 另有可选 snippet 列表。
- **决策是模型的事**：pi 源码没有 `decideIntent()`（grep 验证全空）。
- **权限拦截 `beforeToolCall` 是 core 能力**：`new Agent({ beforeToolCall })` 就能拦，不需要 extension。coding-agent 默认不拦（grep approv/confirm/dangerous 全空，只有白名单）。
- **两层准入**：白名单 `isAllowedTool`（进不进 registry）+ active tools `setActiveToolsByName`（进不进 `agent.state.tools`）。
- **pi 没有**：工具数量上限、top-N 截断、按需懒加载、分组折叠（grep 确认）。
- **真实工具**：read 截断（2000行/50KB + 声明截断 + 续读）；bash 流式 onData + 超时 + killProcessTree。

标注为「我的引申，非 pi 意图」的：能力消除优于运行时防御、按需暴露要应用层自己补。

## 五、new Agent vs createAgentSession（架构判断）

- `new Agent`（pi-agent-core）= 纯 turn 引擎，自己装配一切。适合「已有自己的存储/协议/模型路由，只缺对话内核」。
- `createAgentSession`（pi-coding-agent）= 内部就是 new Agent + 一圈设施（SessionManager、ModelRegistry、ResourceLoader、AgentSession、内置工具、skill/extension 系统）。适合「想要 skill/extension/memory 地基」。
- crbuddy 最初用 new Agent，后因目标变成「通用工作台 + 要 skill/agent/memory/自进化」迁到 createAgentSession。

## 六、crbuddy 实战（真实项目验证）

crbuddy = 基于 pi 的个人工作台（web server + SSE + sqlite + bridge 路由），用 createAgentSession。

加工具的两次 commit（都已 push 到 betaHi/crbuddy）：
- `045ed6a`：get_weather 工具，customTools 方式。
- `3f9bbb1`：把 weather 改成 extension 方式（`weatherExtension` factory + `extensionFactories`），gerrit 保持 customTools。两种方式在同项目并存。

E2E 验证过：问「北京天气」→ 模型发 `get_weather({city:北京})` → tool_end ok:true → 真实温度回答。

关键代码位置（crbuddy）：
- `src/server/chat/tools.ts`：gerritGetCl（customTools）、getWeather（extension）、weatherExtension factory、CRBUDDY_TOOLS、describeTools。
- `src/server/chat/runtime.ts`：createChatSession，loader（noExtensions:true + extensionFactories）+ createAgentSession（noTools:'builtin' + customTools）。

踩过的坑（已写进 06 文章）：
- 自传 DefaultResourceLoader 必须自己 `await loader.reload()`（createAgentSession 只对自建 loader reload，sdk.ts:207）。
- `noExtensions:true` 只挡磁盘发现，不影响内联 extensionFactories（resource-loader.ts:395）。
- ToolDefinition 的 `label` 是必填。
- DefaultResourceLoader 的 cwd/agentDir 必填。
- createAgentSession 是 async，要 await。
