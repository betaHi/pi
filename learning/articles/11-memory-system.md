这一篇和前面几篇不太一样。前面讲的都是 pi 已经实现的机制，这一篇要先说清一件事：**长期记忆不是 pi 的内置功能，而是应用层要自己搭的系统。** pi 提供的是"能挂记忆的地基"，不是记忆本身。

先把这个边界坐实，再看 pi 到底给了哪些地基。

## 一、pi 没有内置长期记忆

检索整个仓库可以确认：

- 搜 `embedding`、`vectorstore`、`retrieval`、`semantic search`、`long-term memory`，没有相关实现；
- 搜 `memory`，只有若干处 `InMemory`——是内存缓存（比如内存里的鉴权存储、会话仓库），不是长期记忆。

所以 pi 不提供记忆的提取、向量检索、去重、外部存储。一个常见的误读是把 pi 的 session 存储当成"长期记忆"——它不是，它只是当前会话的记录（Session 篇讲过，一个会话一个 JSONL 文件）。

那 pi 给了什么？答案是：**注入点和原语**。一个记忆系统通常要做四件事——提取、存储、检索、注入——pi 只在最后一件"注入"上给了现成机制，前三件完全是应用层的事。

## 二、注入原语之一：context hook（瞬态）

extension 可以注册一个 `context` handler，在每次 LLM 调用前改写整组 messages（Extension 篇的事件表里就有这一项）。运行时，pi 把当前 messages 交给每个 context handler，依次改写，返回新的 messages。

用它注入记忆的特点：

- **瞬态**：每一轮都重新算，注入的内容不进 session 树、不留痕；
- 适合"这一轮检索到的相关记忆，临时插进去"——依赖当前问题、用完即弃。

pi 自带的示例里有 extension 用 `context` 事件改上下文（虽然那个例子做的不是记忆，但证明这条注入路径是通的）。

## 三、注入原语之二：custom_message 进树（持久）

另一条路是往 session 树里加一个 `custom_message` 类型的 entry，它会进入模型上下文。源码里这个方法的注释写得很明确——这种 entry 参与 LLM 上下文。

用它注入记忆的特点：

- **持久**：进 session 树、留痕、随会话恢复（Session 篇的 append-only 树）；
- 投影时进入上下文：`custom_message` entry 先被投影成一条消息，再由 `convertToLlm` 翻成 user 消息（Context 篇讲过这个映射，那里表格里的 `custom` 指的就是这一步的消息角色，注意和这里的 `custom_message` entry 是两个层级）；
- 适合"记住这条，之后每次都带上"——稳定的长期上下文。

两条路对照：

| | context hook | custom_message 进树 |
|---|---|---|
| 生命周期 | 瞬态，每轮现算 | 持久，进树可恢复 |
| 是否留痕 | 不留 | 留 |
| 适合 | 按当前问题检索的相关记忆 | 固定要记住的事实或偏好 |

选哪条，取决于这段记忆是"这次相关就临时带"还是"永久记住"。这个判断是记忆系统的设计决定，pi 两条都给了。（这一段的选择建议是顺着机制的推断，不是 pi 文档的规定；两个方法本身的行为是源码确认的。）

## 四、两个辅助原语

除了注入，pi 还有两个点能被记忆系统利用。

**session 事件**：Extension 篇的事件表里，`turn_end`、`message_end`、`session_shutdown` 这些点，可以用作提取的时机——一轮结束时判断"这轮有没有值得记的东西"。pi 给的是时机，具体抽取什么、怎么抽，是应用层写的。

**项目文件**：`AGENTS.md` / `CLAUDE.md` 这类文件走 `<project_context>` 进 system prompt（Context 篇讲过）。这相当于一种静态记忆——项目级的固定约定，一直在上下文里。适合放不变的长期事实，但它是静态的，不能在对话中动态更新。

## 五、一个记忆系统落到 pi 上会是什么样

下面这段是顺着上面的原语推出来的设计，不是 pi 的源码，标清楚。

```
提取：extension 挂 turn_end / session_shutdown 事件 → 判断本轮有无值得记的 → 抽成条目
存储：写到外部 store（pi 不管）—— 数据库 / 向量库 / 文件
检索：新一轮开始，按当前问题从 store 找相关条目（pi 不管）
注入：
  - 瞬态相关记忆 → context hook 临时插进 messages
  - 固定事实、偏好 → custom_message 进树，持久保留
```

pi 的边界很清楚：它是"记忆能挂上来的地基"，不是记忆本身。提取的判断、存储的介质、检索的算法、去重的策略，全在应用层。pi 负责的只有一件——让记忆能进上下文，而且给了瞬态和持久两种进法。

## 结尾

这一篇没有很多源码细节，因为 pi 在 memory 这块本来就是"提供地基、不提供实现"。把它讲清楚本身有价值：知道边界在哪，才不会误以为 pi 自带长期记忆，也才知道自己要补的是提取、存储、检索这三块。

下一篇讲自我进化——它和 memory 用的是同一批地基（session 事件、extension hook、资源加载），但解决的是另一个问题：memory 是往上下文里加内容，自我进化是改产生上下文的规则。
